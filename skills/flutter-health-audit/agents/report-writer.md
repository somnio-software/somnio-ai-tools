Read and follow ALL instructions in `references/report-generator.md` and `references/report-format-enforcer.md` — these two references are the single source of truth for the complete scoring formula, mandatory section structure, and formatting rules. `references/report-generator.md` is ALSO the single source of truth for the nine weight literals: read them from there, do not invent or restate them from memory. Also read `assets/report-template.md` for the canonical template.

## Inputs

Read ALL of the following artifacts (read only what exists; handle missing files with the fallback text specified in references/report-generator.md):

- `reports/.artifacts/flutter-health-audit/step_00_test_coverage.md` — coverage preflight (MANDATORY for Section 7)
- `reports/.artifacts/flutter-health-audit/step_01_repository_inventory.md`
- `reports/.artifacts/flutter-health-audit/step_02_config_analysis.md`
- `reports/.artifacts/flutter-health-audit/step_03_cicd_analysis.md`
- `reports/.artifacts/flutter-health-audit/step_04_testing_analysis.md`
- `reports/.artifacts/flutter-health-audit/step_05_code_quality.md`
- `reports/.artifacts/flutter-health-audit/step_06_documentation_analysis.md`
- `reports/.artifacts/flutter-health-audit/step_07_harness_analysis.md`
- `reports/.artifacts/flutter-health-audit/step_08_state_management_analysis.md`

Do NOT re-read any raw source files from the project under audit.

## Scoring

Compute nine section scores (0–100 integers) from the artifact evidence, then compute the overall score:

```
overall_score = round( Σ(section_score × weight) )
```

Weights are defined in `references/report-generator.md` — that file is the single source of truth; do not restate the numbers here. Read them from there both to compute `overall_score` and to render the `## Appendix: Scoring Methodology` table (see Output below) — the two must use the identical nine literals.

Labels: 85–100 = Strong, 70–84 = Fair, 0–69 = Weak. Standard mathematical rounding (0.5 rounds up). No subjective adjustments.

## Output

**Report path**: `reports/<YYYY-MM-DD>-<project>-flutter-health-audit.md`

Create the directory first: `mkdir -p reports`

The report MUST contain all 15 numbered sections in the exact order specified by `references/report-format-enforcer.md` (there is no "Quality Index" section), followed by the two unnumbered trailing blocks: `## Appendix: Scoring Methodology` and `## Report Metadata`.

Coverage appears in EXACTLY TWO places, both required:
- Directly under the Section 2 (At-a-Glance Scorecard) table: the `> **Test Coverage:**` line plus its fallback second line, copied/derived from `reports/.artifacts/flutter-health-audit/step_00_test_coverage.md`.
- Section 7 (Testing): the `Code Coverage:` and `Coverage Breakdown:` fields, copied VERBATIM from `reports/.artifacts/flutter-health-audit/step_00_test_coverage.md`, between `Score` and `Key Findings`.
Do NOT restate a coverage percentage anywhere else (Additional Metrics included). Section 11 (AI Harness & Adoption) uses `### Harness Coverage`, never a bare `### Coverage`.

Before `## Report Metadata`, render `## Appendix: Scoring Methodology` with the nine weight literals read from `references/report-generator.md` (never invented here) — see `assets/report-template.md` for the exact block shape. This appendix is the ONLY place in the report where weights may appear; the Section 2 scorecard table never carries a Weight column.

After the appendix, append the mandatory metadata block as specified in `SKILL.md`, as a Markdown table:

```markdown
## Report Metadata

| Field | Value |
|-------|-------|
| Generated by | [Plugin Name] v[Plugin Version] |
| Skill | flutter-health-audit |
| Date | [YYYY-MM-DD] |
| Somnio AI Tools | https://github.com/somnio-software/somnio-ai-tools |
```

To resolve the source and version: look for `.claude-plugin/plugin.json` by traversing up from the skill directory. If found, read `name` and `version` from it. If not found, use `Somnio CLI` as the name and `unknown` as the version.

## Validation

Before writing the report, verify:
- All 15 numbered sections are present and in order (no "Quality Index"), plus `## Appendix: Scoring Methodology` and `## Report Metadata`
- All scores are integers with correct labels
- The overall score matches the weighted formula, using weights read from `references/report-generator.md`
- The `> **Test Coverage:**` line is present under the Section 2 scorecard, and Section 7 contains the verbatim `Code Coverage:` / `Coverage Breakdown:` fields — coverage appears nowhere else
- Section 11 uses `### Harness Coverage`, not a bare `### Coverage`
- The Section 2 scorecard table has no Weight column; weights appear only in the Appendix: Scoring Methodology
- `## Report Metadata` is rendered as a `| Field | Value |` table
- All evidence references actual artifact content (not invented)
- No recommendations for new languages/translations, CODEOWNERS, SECURITY.md, or platform-specific deployment workflows

On completion, output: `WAVE 4 COMPLETED: Report written to reports/<YYYY-MM-DD>-<project>-flutter-health-audit.md. Overall score: [N]/100 ([Label]).`
