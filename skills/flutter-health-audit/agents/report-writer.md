Read and follow ALL instructions in `references/report-generator.md` and `references/report-format-enforcer.md` — these two references are the single source of truth for the complete scoring formula, mandatory section structure, and formatting rules. Also read `assets/report-template.md` for the canonical template.

## Inputs

Read ALL of the following artifacts (read only what exists; handle missing files with the fallback text specified in references/report-generator.md):

- `reports/.artifacts/flutter_health/step_00_test_coverage.md` — coverage preflight (MANDATORY for Section 7)
- `reports/.artifacts/flutter_health/step_01_repository_inventory.md`
- `reports/.artifacts/flutter_health/step_02_config_analysis.md`
- `reports/.artifacts/flutter_health/step_03_cicd_analysis.md`
- `reports/.artifacts/flutter_health/step_04_testing_analysis.md`
- `reports/.artifacts/flutter_health/step_05_code_quality.md`
- `reports/.artifacts/flutter_health/step_06_documentation_analysis.md`
- `reports/.artifacts/flutter_health/step_07_harness_analysis.md`
- `reports/.artifacts/flutter_health/step_08_state_management_analysis.md`

Do NOT re-read any raw source files from the project under audit.

## Scoring

Compute nine section scores (0–100 integers) from the artifact evidence, then compute the overall score using the exact weighted formula from `references/report-generator.md`:

```
overall_score = round(
  Tech_Stack       × 0.18 +
  Architecture     × 0.18 +
  State_Mgmt       × 0.18 +
  Repos_Data_Layer × 0.10 +
  Testing          × 0.10 +
  Code_Quality     × 0.10 +
  Docs_Ops         × 0.03 +
  CICD             × 0.03 +
  Harness          × 0.10
)
```

Labels: 85–100 = Strong, 70–84 = Fair, 0–69 = Weak. Standard mathematical rounding (0.5 rounds up). No subjective adjustments.

## Output

**Report path**: `reports/flutter_audit.md`

Create the directory first: `mkdir -p reports`

The report MUST contain all 16 sections in the exact order specified by `references/report-format-enforcer.md`. Section 7 (Testing) MUST include the `Code Coverage:` and `Coverage Breakdown:` lines copied VERBATIM from `reports/.artifacts/flutter_health/step_00_test_coverage.md`.

After the final section, append the mandatory metadata block as specified in `SKILL.md`:

```
---
Generated by: [plugin name or "Somnio CLI"] v[version]
Skill: flutter-health-audit
Date: [YYYY-MM-DD]
Somnio AI Tools: https://github.com/somnio-software/somnio-ai-tools
---
```

To resolve the source and version: look for `.claude-plugin/plugin.json` by traversing up from the skill directory. If found, read `name` and `version` from it. If not found, use `Somnio CLI` as the name and `unknown` as the version.

## Validation

Before writing the report, verify:
- All 16 sections are present and in order
- All scores are integers with correct labels
- The overall score matches the weighted formula
- Section 7 contains verbatim coverage lines
- All evidence references actual artifact content (not invented)
- No recommendations for new languages/translations, CODEOWNERS, SECURITY.md, or platform-specific deployment workflows

On completion, output: `WAVE 4 COMPLETED: Report written to reports/flutter_audit.md. Overall score: [N]/100 ([Label]).`
