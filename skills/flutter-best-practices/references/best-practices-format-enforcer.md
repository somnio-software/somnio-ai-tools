# Flutter Best Practices Report Format Enforcer

> Enforce Markdown report format for the Flutter Best Practices Check report based on the template in assets/report-template.md.

---

## MANDATORY REPORT STRUCTURE

The report MUST contain exactly these 7 numbered sections, in this order, followed by two unnumbered closing blocks:

1. Executive Summary
2. Score Breakdown
3. Testing Quality
4. Architecture Compliance
5. Code Standards
6. Prioritized Recommendations
7. Evidence Index

Then, unnumbered:
- Appendix: Scoring Methodology
- Report Metadata

## FORMAT REQUIREMENTS

**CRITICAL**: All analysis outputs MUST follow these rules:

1.  **USE MARKDOWN FORMATTING**:
    *   `#` for main title, `##` for sections, `###` for subsections
    *   `**bold**` for scores, labels, and key terms
    *   Backticks for file paths and code references
    *   `- ` for bullet points

2.  **HEADING FORM**:
    *   Numbered sections use `## N. Section Name` (e.g. `## 3. Testing Quality`).
    *   The literal word "Section" MUST NOT appear in any heading text — headings name the
        section directly (`## 3. Testing Quality`, never `## Section 3. Testing Quality`).
    *   Code refs: `` `path/to/file.dart:42` ``
    *   File paths: `` `lib/features/auth/auth_bloc.dart:42` ``

3.  **SCORE BREAKDOWN TABLE** (`## 2. Score Breakdown`):
    *   Columns are exactly `| Section | Score | Label |` — no Weight column.
    *   One row per section (Testing Quality, Architecture Compliance, Code Standards), plus a
        final `**Weighted Overall**` row.
    *   The weighted overall value is computed per `references/best-practices-generator.md` —
        never re-derived or approximated here.
    *   Immediately below the table, a scoring-legend blockquote, exactly:
        `> **Scoring:** Strong (85–100) · Fair (70–84) · Weak (0–69)`
        (en dash `–` U+2013 between the bounds, middle dot `·` U+00B7 between bands).

4.  **SECTION STRUCTURE**:
    Each of sections 3-5 (Testing Quality, Architecture Compliance, Code Standards) must include,
    in this order, exactly the subsections `assets/report-template.md` renders:
    - `**Description:**` (one-sentence summary)
    - `**Score:**` (0-100 integer, with label)
    - `### Key Findings` (3-7 bullet points with dashes)
    - `### Violations` (one bullet per finding, each naming a specific file in backticks —
      this family's name for the file-reference list; it is NOT called "Evidence")
    - `### Recommendations` (prioritized actions)

5.  **SCORING LABELS**:
    - Scores are integers 0-100.
    - Strong: 85-100
    - Fair: 70-84
    - Weak: 0-69

6.  **EVIDENCE INDEX** (`## 7. Evidence Index`):
    - List every file referenced in sections 3-5, organized by category (e.g. Test files,
      Widget/Screen files, BLoC/Cubit files, Repository/Data files, Model files).

7.  **CLOSING APPENDIX**:
    - The report MUST close with an unnumbered `## Appendix: Scoring Methodology` block, placed
      between the Evidence Index section and `## Report Metadata`.
    - Its `| Section | Weight |` rows must match this skill's own Score Breakdown rows (Testing
      Quality, Architecture Compliance, Code Standards) and sum to 100%.

8.  **WEIGHTS APPEAR IN ONE PLACE ONLY**:
    - Weights appear ONLY in the closing `## Appendix: Scoring Methodology` block and in
      `references/best-practices-generator.md`.
    - Weights must NEVER appear as a column in the `## 2. Score Breakdown` table.

9.  **REPORT METADATA**:
    - The report MUST close with an unnumbered `## Report Metadata` `| Field | Value |` table
      (Generated by, Skill, Date, Somnio AI Tools link) as the final block.

10. **FILE REFERENCES FORMAT**:
    - Always use: "path/to/file.dart:line_number"
    - Example: "lib/features/auth/auth_bloc.dart:42 — BLoC accesses Dio directly"

Recommendations:
