# Flutter Best Practices Report Generator

> Consolidate all analysis findings into a comprehensive best practices report using the standard template format.

---

## REPORT GENERATION INSTRUCTIONS

1.  **GATHER ALL ANALYSIS OUTPUTS**:
    Collect findings from all analysis rules:
    - Testing Quality Analysis
    - Architecture Compliance Analysis
    - Code Standards Analysis

2.  **COMPUTE OVERALL SCORE**: Calculate weighted average:
    - Testing Quality: 30%
    - Architecture Compliance: 40%
    - Code Standards: 30%

3.  **PRIORITIZE FINDINGS**:
    Rank all violations by:
    - Critical: Layer-separation violations (BLoC/Cubit accessing `ApiClient`/`Dio` directly instead of a Repository, Repositories returning DTOs to the Business Layer), empty `catch` blocks that swallow errors silently
    - High: Hardcoded dependencies instead of constructor injection, mutable model fields / missing `Equatable`, tests with no assertions
    - Medium: Missing widget tests or `bloc_test` structure (`group`/`build`/`act`/`expect`), verbose or unclear test naming, `print()` statements instead of the `logging` package
    - Low: Excessive class inheritance where composition would be better, verbose boilerplate, naming/formatting issues

4.  **GENERATE REPORT USING TEMPLATE**:
    Use the template at:
     "assets/report-template.md"

## REPORT SECTIONS

1. EXECUTIVE SUMMARY
   - Overall Score with label (Strong/Fair/Weak)
   - Top 3 Strengths
   - Top 3 Critical Issues
   - Immediate Action Items

2. SCORE BREAKDOWN
   - Testing Quality: XX/100 (Label)
   - Architecture Compliance: XX/100 (Label)
   - Code Standards: XX/100 (Label)

3. TESTING QUALITY
   - Test Naming Conventions
   - Assertion Quality
   - Test Structure & Atomicity (grouping, setup/teardown, mocking)
   - Bloc Testing Specifics
   - Widget Testing Specifics
   - Violations and Recommendations

4. ARCHITECTURE COMPLIANCE
   - Layer Boundary Violations (Presentation / Business Logic / Repository / Data)
   - Dependency Injection
   - Repository Pattern
   - Composition over Inheritance
   - Violations and Recommendations

5. CODE STANDARDS
   - JSON Model Best Practices (Equatable, copyWith, fromJson/toJson)
   - Code Generosity & Conciseness
   - Error Handling
   - Formatting & Layout
   - Violations and Recommendations

6. PRIORITIZED RECOMMENDATIONS
   - Critical (Must Fix)
   - High Priority
   - Medium Priority
   - Low Priority (Nice to Have)

7. EVIDENCE INDEX
   - All file references organized by category

APPENDIX: SCORING METHODOLOGY (unnumbered — no `## N.` prefix)
   - A `| Section | Weight |` table: one row per scored section, in the same
     order as the Score Breakdown rows and with byte-identical row labels,
     using the percentages from step 2 above, closing with a
     `| **Total** | **100%** |` row
   - The rounding rule and the scoring bands
   - Weights appear ONLY here and in this file — NEVER as a column in the
     Score Breakdown table

REPORT METADATA (unnumbered — no `## N.` prefix)
   - A `| Field | Value |` table with Generated by, Skill, Date and the
     Somnio AI Tools link, exactly as `assets/report-template.md` renders it.
     NOT a plain-text `---`-delimited list.

## OUTPUT REQUIREMENTS

- Use Markdown format (# headers, **bold**, `backtick` file paths)
- Include all file references with line numbers
- Provide specific, actionable recommendations
- Include code examples where helpful
- Score each section 0-100 with label
- List violations with severity level
- Emit the numbered sections in the SAME ORDER as the template — do not
  reorder them by score, severity or any other criterion
- Close with the two unnumbered blocks above, in that order: Appendix:
  Scoring Methodology, then Report Metadata
